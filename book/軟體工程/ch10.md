# 第 10 章：AI 導向程式設計

## AI 導向的程式設計概論

AI 導向程式設計（AI-Oriented Programming）是一套撰寫程式碼的方法論，目標是讓 AI 程式碼生成工具能夠更準確、更穩定地理解開發者的意圖，並產出高品質的程式碼。

傳統程式設計關注的是「人讀懂程式碼」，但 AI 導向程式設計進一步考慮「AI 如何解讀程式碼」。這並非取代傳統軟體工程原則，而是在其基礎之上，針對 AI 生成模型的特點進行最佳化。

AI 模型在本質上是基於機率分布的預測引擎。當開發者撰寫程式碼時，AI 工具會根據上下文推測接下來最可能的 token 序列。因此，**可預測性**與**一致性**成為 AI 導向程式設計的兩大核心原則。

### 核心原則對照

傳統程式設計追求可讀性與可維護性；AI 導向程式設計則在此之上增加三個維度：

1. **模式辨識最佳化**：程式碼中的慣用模式越接近訓練資料中的常見模式，AI 的生成準確度越高
2. **語境豐富度**：提供足夠的上下文資訊，幫助 AI 理解程式碼的目的與限制
3. **模糊性消除**：減少語義模糊的寫法，降低 AI 誤判的機率

## 為 AI 程式碼生成最佳化的編寫方式

### 不良寫法 vs AI 友善寫法

**不良範例：模糊的邏輯**

```python
def process(data):
    result = []
    for x in data:
        if x > 0:
            result.append(x * 2)
    return result
```

這個函數的名稱 `process` 完全無法表達它在做什麼。AI 在生成對此函數的呼叫時，無法從名稱推測其行為。

**AI 友善版本：**

```python
def double_positive_numbers(numbers: list[float]) -> list[float]:
    filtered = [num for num in numbers if num > 0]
    return [num * 2 for num in filtered]
```

名稱 `double_positive_numbers` 精確描述了行為，型別註解讓 AI 知道輸入輸出格式，列表推導式則讓邏輯更簡潔。

### 避免魔法數字與模糊常數

**不良範例：**

```python
def calculate(amount):
    return amount * 0.15
```

**AI 友善版本：**

```python
TAX_RATE = 0.15

def calculate_sales_tax(amount: float) -> float:
    return amount * TAX_RATE
```

AI 看到命名常數 `TAX_RATE` 後，在生成相關程式碼時能夠正確引用，而不是猜測 `0.15` 的意義。

## 清晰的命名與型別系統

### 命名原則

命名是 AI 理解程式碼最重要的線索之一。好的命名讓 AI 能夠推斷變數的用途、型別和生命周期。

| 命名風格 | AI 理解度 | 範例 |
|---------|----------|------|
| 模糊縮寫 | 低 | `def calc_tax(a, r):` |
| 部分描述 | 中 | `def calculate_tax(amount, rate):` |
| 完整語義 | 高 | `def calculate_sales_tax(subtotal: float, tax_rate: float) -> float:` |

### 型別系統的雙重價值

型別註解不僅幫助開發者，也為 AI 提供關鍵資訊：

```python
from datetime import datetime
from decimal import Decimal

class Order:
    def __init__(self, order_id: str, items: list["OrderItem"]) -> None:
        self.order_id = order_id
        self.items = items
        self.created_at: datetime = datetime.now()
        self.total: Decimal = Decimal("0.00")

    def calculate_total(self) -> Decimal:
        return sum(item.price for item in self.items)
```

當 AI 看到 `order_id: str`，它在生成相關程式碼時就不會嘗試將 order_id 用作整數。型別系統約束了 AI 的生成空間，使結果更精準。

### 泛型與型別別名

對於複雜型別，使用型別別名可以顯著提升 AI 的生成品質：


## 良好的函數粒度與職責分離

### 函數長度與 AI 生成

AI 生成程式碼時，短函數的生成準確率顯著高於長函數。研究顯示，當函數長度在 10-30 行之間時，AI 的生成成功率最高。

**不良範例：單一巨型函數**

```python
def process_user_registration(request):
    # 驗證輸入
    if not request.get("email"):
        raise ValueError("Email is required")
    if not request.get("password"):
        raise ValueError("Password is required")
    if len(request["password"]) < 8:
        raise ValueError("Password too short")

    # 檢查重複
    user = db.query("SELECT * FROM users WHERE email = ?", request["email"])
    if user:
        raise ValueError("Email already exists")

    # 建立使用者
    hashed = hash_password(request["password"])
    user_id = db.execute(
        "INSERT INTO users (email, password) VALUES (?, ?)",
        request["email"], hashed
    )

    # 發送歡迎郵件
    send_email(request["email"], "Welcome!", "Thank you for registering")

    # 記錄日誌
    log(f"User registered: {user_id}")

    return {"user_id": user_id, "status": "created"}
```

**AI 友善版本：良好分解的函數**

```python
class RegistrationService:
    def __init__(self, db: Database, mailer: Mailer, logger: Logger) -> None:
        self.db = db
        self.mailer = mailer
        self.logger = logger

    def register(self, request: RegistrationRequest) -> RegistrationResult:
        self._validate_request(request)
        self._check_duplicate_email(request.email)
        user_id = self._create_user(request)
        self.mailer.send_welcome_email(request.email)
        self.logger.info(f"User registered: {user_id}")
        return RegistrationResult(user_id=user_id, status="created")

    def _validate_request(self, request: RegistrationRequest) -> None:
        if not request.email:
            raise ValidationError("Email is required")
        if not request.password or len(request.password) < 8:
            raise ValidationError("Password must be at least 8 characters")

    def _check_duplicate_email(self, email: str) -> None:
        if self.db.find_user_by_email(email):
            raise DuplicateEmailError(f"Email already exists: {email}")

    def _create_user(self, request: RegistrationRequest) -> int:
        hashed = hash_password(request.password)
        return self.db.insert_user(
            email=request.email,
            password_hash=hashed
        )
```

每個函數都有明確的單一職責，AI 可以獨立理解、生成和測試每個小函數。

### 單一職責原則（SRP）與 AI

當每個函數只做一件事時，AI 的生成任務就變得單純：

## 撰寫有助 AI 理解的註解與文件

### Docstring 的結構化撰寫

AI 對結構化文件的理解效果遠優於散文式描述：

```python
def calculate_discount(
    price: float,
    customer_type: str,
    loyalty_years: int
) -> float:
    """Calculate the discount amount for a customer.

    Applies business rules based on customer type and loyalty duration.
    The discount is capped at the maximum allowed percentage.

    Args:
        price: The base price before discount
        customer_type: One of "regular", "premium", "vip"
        loyalty_years: Number of years since customer registration

    Returns:
        The discount amount (not the final price)

    Raises:
        ValueError: If customer_type is invalid or price is negative

    Examples:
        >>> calculate_discount(100.0, "vip", 5)
        30.0
        >>> calculate_discount(100.0, "regular", 1)
        5.0
    """
    DISCOUNT_RATES = {
        "regular": 0.05,
        "premium": 0.10,
        "vip": 0.20,
    }
    if customer_type not in DISCOUNT_RATES:
        raise ValueError(f"Invalid customer type: {customer_type}")

    rate = DISCOUNT_RATES[customer_type]
    loyalty_bonus = min(loyalty_years * 0.01, 0.10)
    total_rate = min(rate + loyalty_bonus, 0.30)
    return round(price * total_rate, 2)
```

這種結構化的 docstring 讓 AI 在生成測試程式碼、呼叫範例或替代實作時，擁有完整的規格資訊。

### 行內註解的策略

行內註解應說明「為什麼」而非「是什麼」：

```python
def retry_with_backoff(fn: Callable, max_retries: int = 3) -> Any:
    for attempt in range(max_retries):
        try:
            return fn()
        except TemporaryError as e:
            if attempt == max_retries - 1:
                raise
            # Exponential backoff to avoid overwhelming the server
            time.sleep(2 ** attempt * 0.1)
```

AI 看到註解說明目的後，在生成類似的重試邏輯時更容易套用正確的模式。


### 統一回傳型別

```python
# 不一致（AI 難以預測）
def find_user(name: str):
    if user := db.find(name):
        return user
    return None  # 有時回傳 None，有時不回傳

def find_users(active: bool):
    return db.find_all(active=active) or []  # 有時回傳 list，有時回傳 None

# 一致

    return db.find(name)

def find_users(active: bool) -> list[User]:
    return db.find_all(active=active) or []
```

## AI-friendly 的設計模式

### Factory 模式

AI 擅長生成遵循明確模式的程式碼。Factory 模式為 AI 提供了清晰的生成架構：

```python
from abc import ABC, abstractmethod

class ReportExporter(ABC):
    @abstractmethod
    def export(self, data: dict) -> str: ...

class PDFExporter(ReportExporter):
    def export(self, data: dict) -> str:
        return f"PDF content: {data}"

class CSVExporter(ReportExporter):
    def export(self, data: dict) -> str:
        return ",".join(str(v) for v in data.values())

class HTMLExporter(ReportExporter):
    def export(self, data: dict) -> str:
        return "<html><body>" + "".join(f"<p>{k}: {v}</p>" for k, v in data.items()) + "</body></html>"

class ReportExporterFactory:
    exporters = {
        "pdf": PDFExporter,
        "csv": CSVExporter,
        "html": HTMLExporter,
    }

    @classmethod
    def create(cls, format_type: str) -> ReportExporter:
        exporter_class = cls.exporters.get(format_type)
        if exporter_class is None:
            raise ValueError(f"Unsupported format: {format_type}")
        return exporter_class()
```

AI 看到這個模式後，若需要新增 `JSONExporter`，只需遵循 `class JSONExporter(ReportExporter):` 的模式即可生成正確的程式碼。

### Builder 模式

Builder 模式特別適合 AI 生成，因為它將複雜物件的建構分解為一系列鏈式方法呼叫：

```python
class QueryBuilder:
    def __init__(self) -> None:
        self._select: list[str] = []
        self._from_table: str = ""
        self._where: list[str] = []
        self._order_by: list[str] = []
        self._limit: Optional[int] = None

    def select(self, columns: list[str]) -> "QueryBuilder":
        self._select = columns
        return self

    def from_table(self, table: str) -> "QueryBuilder":
        self._from_table = table
        return self

    def where(self, condition: str) -> "QueryBuilder":
        self._where.append(condition)
        return self

    def order_by(self, column: str, direction: str = "ASC") -> "QueryBuilder":
        self._order_by.append(f"{column} {direction}")
        return self

    def limit(self, n: int) -> "QueryBuilder":
        self._limit = n
        return self

    def build(self) -> str:
        query = f"SELECT {', '.join(self._select) if self._select else '*'}"
        query += f" FROM {self._from_table}"
        if self._where:
            query += f" WHERE {' AND '.join(self._where)}"
        if self._order_by:
            query += f" ORDER BY {', '.join(self._order_by)}"
        if self._limit is not None:
            query += f" LIMIT {self._limit}"
        return query
```

AI 可以輕鬆透過提示 `QueryBuilder().select(...).from_table(...).where(...)` 來生成正確的使用方式。

### Repository 模式

```python
from abc import ABC, abstractmethod

class UserRepository(ABC):
    @abstractmethod
    def find_by_id(self, user_id: int) -> Optional[User]: ...
    @abstractmethod
    def find_by_email(self, email: str) -> Optional[User]: ...
    @abstractmethod
    def save(self, user: User) -> int: ...
    @abstractmethod
    def delete(self, user_id: int) -> bool: ...

class PostgresUserRepository(UserRepository):
    def __init__(self, connection: Connection) -> None:
        self.conn = connection

    def find_by_id(self, user_id: int) -> Optional[User]:
        row = self.conn.execute(
            "SELECT id, name, email FROM users WHERE id = %s", (user_id,)
        ).fetchone()
        return User(*row) if row else None

    def find_by_email(self, email: str) -> Optional[User]:
        row = self.conn.execute(
            "SELECT id, name, email FROM users WHERE email = %s", (email,)
        ).fetchone()
        return User(*row) if row else None

    def save(self, user: User) -> int:
        cursor = self.conn.execute(
            "INSERT INTO users (name, email) VALUES (%s, %s) RETURNING id",
            (user.name, user.email)
        )
        return cursor.fetchone()[0]

    def delete(self, user_id: int) -> bool:
        cursor = self.conn.execute(
            "DELETE FROM users WHERE id = %s", (user_id,)
        )
        return cursor.rowcount > 0
```

Repository 模式讓 AI 在生成測試時可以輕鬆 mock 資料層，或在切換資料庫時生成對應的實作。

### C/C++：系統程式設計

C/C++ 的指標操作和記憶體管理對 AI 是較大的挑戰，但在系統程式設計領域仍然不可或缺：

```python
# 模擬低階操作的抽象
class MemoryBuffer:
    def __init__(self, size: int) -> None:
        self._buffer = bytearray(size)
        self._size = size
        self._position = 0

    def write(self, data: bytes) -> int:
        available = self._size - self._position
        to_write = min(len(data), available)
        self._buffer[self._position:self._position + to_write] = data[:to_write]
        self._position += to_write
        return to_write

    def read(self, length: int) -> bytes:
        available = self._size - self._position
        to_read = min(length, available)
        result = bytes(self._buffer[self._position:self._position + to_read])
        self._position += to_read
        return result

    def seek(self, position: int) -> None:
        if position < 0 or position > self._size:
            raise ValueError("Invalid position")
        self._position = position
```

### 類別生成

```python
# AI 生成的完整類別
class RateLimiter:
    """Token bucket rate limiter."""

    def __init__(self, max_requests: int, window_seconds: float) -> None:
        self.max_requests = max_requests
        self.window_seconds = window_seconds
        self.tokens: dict[str, list[float]] = {}

    def is_allowed(self, key: str) -> bool:
        now = time.time()
        if key not in self.tokens:
            self.tokens[key] = []

        self.tokens[key] = [
            t for t in self.tokens[key]
            if now - t < self.window_seconds
        ]

        if len(self.tokens[key]) >= self.max_requests:
            return False

        self.tokens[key].append(now)
        return True

    def remaining(self, key: str) -> int:
        now = time.time()
        if key not in self.tokens:
            return self.max_requests
        active = sum(
            1 for t in self.tokens[key]
            if now - t < self.window_seconds
        )
        return self.max_requests - active
```

```python
# 第一輪：生成基礎結構

    def __init__(self) -> None:
        self.items: list[CartItem] = []

class ShoppingCart:
    def __init__(self) -> None:
        self.items: list[CartItem] = []

    def add_item(self, item: CartItem) -> None:
        for existing in self.items:
            if existing.product_id == item.product_id:
                existing.quantity += item.quantity
                return
        self.items.append(item)

    def remove_item(self, item_id: str) -> bool:
        for i, item in enumerate(self.items):
            if item.product_id == item_id:
                self.items.pop(i)
                return True
        return False

    def calculate_total(self) -> float:
        return sum(item.price * item.quantity for item in self.items)

# 第三輪：新增錯誤處理與邊界條件
class ShoppingCart:
    def __init__(self, max_items: int = 100) -> None:
        self.items: list[CartItem] = []
        self.max_items = max_items

    def add_item(self, item: CartItem) -> None:
        if not isinstance(item, CartItem):
            raise TypeError("Expected CartItem instance")
        if len(self.items) >= self.max_items:
            raise CartFullError("Cart has reached maximum capacity")
        if item.quantity <= 0:
            raise ValueError("Quantity must be positive")
        for existing in self.items:
            if existing.product_id == item.product_id:
                existing.quantity += item.quantity
                return
        self.items.append(item)

    def remove_item(self, item_id: str) -> bool:
        if not item_id:
            raise ValueError("Item ID cannot be empty")
        for i, item in enumerate(self.items):
            if item.product_id == item_id:
                self.items.pop(i)
                return True
        return False

    def calculate_total(self) -> float:
        if not self.items:
            return 0.0
        return round(sum(item.price * item.quantity for item in self.items), 2)
```
