# 金流整合

金流整合是軟體產品從技術實作邁向商業營運的關鍵環節。選擇適合的金流方案直接影響用戶體驗、營運成本與法規合規。

## 金流方案比較

| 方案 | 適用場景 | 手續費 | 撥款週期 | 技術門檻 |
|------|---------|--------|---------|---------|
| 第三方支付閘道 | 電商、服務平台 | 2%~3% + 固定費用 | T+1~T+3 | 低 (API 串接) |
| 信用卡直接收單 | 自有品牌、高流量 | 1.5%~2.5% | T+2~T+5 | 高 (PCI-DSS) |
| 超商代收 / ATM | 非即時付款 | 每筆 15~30 元 | T+1 | 低 |
| 行動支付 (LINE Pay/街口) | 行動用戶 | 2.5%~3.5% | T+1~T+7 | 中 |
| 虛擬貨幣 | 跨境、去中心化 | 1% 以下 | 即時 | 高 |

## 國際市場 — Stripe

[Stripe](https://stripe.com) 是國際軟體公司最通用的金流平台，支援 135+ 貨幣、47+ 國家收款。

### 核心優勢

- **API 品質極高** — 文件完整、SDK 齊全（Python / Rust / Node.js / Go）、Webhook 可靠
- **自動結匯** — 收款自動換算為帳戶所在貨幣，無需手動處理匯率
- **Subscription 套件** — 定期定額、用量計費、Free Trial 內建支援
- **Stripe Connect** — Marketplace / Platform 金流（支援分帳到多個收款帳戶）
- **Radar** — AI 防詐欺引擎，可自訂規則

### Stripe Atlas

[Stripe Atlas](https://stripe.com/atlas) 提供一站式美國公司設立 + 金流開通：

1. **公司型態**：Delaware C-Corp（矽谷標準，接受 VC 投資）
2. **費用**：$500 一次性（含公司設立 + EIN 申請 + Stripe 帳號）
3. **時程**：3~5 個工作天（公司成立）+ 1~2 週（銀行帳戶）
4. **後續義務**：
   - 每年 Delaware Franchise Tax ($225 固定稅)
   - 聯邦申報 (Form 1120) — 建議委託 CPA
   - 州所得稅申報（視營業活動所在州而定）
5. **推薦搭配銀行**：Mercury / Brex / Relay（專為新創設計的網路銀行）

### 串接範例

```python
import stripe
stripe.api_key = "sk_test_..."

# 建立付款 Intent
intent = stripe.PaymentIntent.create(
    amount=2000,        # 單位：美分 ($20.00)
    currency="usd",
    automatic_payment_methods={"enabled": True},
)

# 建立訂閱
price = stripe.Price.create(
    product="prod_...",
    unit_amount=1500,   # $15.00
    currency="usd",
    recurring={"interval": "month"},
)
subscription = stripe.Subscription.create(
    customer="cus_...",
    items=[{"price": price.id}],
)
```

### 多貨幣注意事項

- **定價策略**：以 USD 為基準，當地貨幣價格浮動（建議每月更新匯率）
- **跨境手續費**：非本國卡片可能額外收 1%~2%（跨境費）
- **退款**：以原收款貨幣退款，匯率損失由商家承擔
- **稅務**：部分國家要求對當地消費者收取 VAT/GST（Stripe Tax 可自動計算）

## 第三方支付閘道 (台灣)

### 常見閘道

- **藍新科技 (NewebPay)** — 支援信用卡、ATM、超商、LINE Pay，手續費 2.5%~3%
- **綠界科技 (ECPay)** — 市佔最高，支援多元付款，手續費 2%~2.8%
- **TapPay** — 專注信用卡 + Apple Pay，技術文件較好，手續費 2.2%~2.8%

### 串接流程

1. 申請特店帳號（需公司登記證明）
2. 取得商店代號（Merchant ID）+ 金鑰（Hash Key / IV）
3. 選擇串接方式：
   - **嵌入式**：用戶跳轉到閘道頁面付款
   - **直連式**：API 直接傳送卡號（需 PCI-DSS）
4. 測試環境驗證（Test Mode）
5. 正式上線（Production）

## 信用卡收款

### PCI-DSS 合規層級

| 層級 | 年交易量 | 要求 |
|------|---------|------|
| 第 1 級 | >600 萬筆 | 每年現場稽核 + ASV 掃描 |
| 第 2 級 | 100~600 萬筆 | 每年自評問卷 + ASV 掃描 |
| 第 3 級 | 2~100 萬筆 | 每年自評問卷 + ASV 掃描 |
| 第 4 級 | <2 萬筆 | 自評問卷或 ASV 掃描 |

### 3D 驗證 (3D Secure)

- **3DS 1.0**：跳轉到銀行頁面輸入密碼（轉換率下降 10%~20%）
- **3DS 2.0**：無密碼驗證（基於裝置指紋 + 行為分析），轉換率接近無驗證
- 使用 Stripe / TapPay 可簡化 3DS 2.0 串接

## 訂閱制金流

### 定期定額挑戰

- 信用卡過期（每月約 5%~10% 自動續約失敗）
- 持卡人換卡（Visa Account Updater 可自動更新）
- 扣款失敗重試策略：
  - 失敗後 3 天、7 天、15 天各重試一次
  - 超過 30 天仍未成功 → 暫停服務並通知用戶
- 留存率：第一年約 60%~80%，第二年約 40%~60%

## 對帳 (Reconciliation)

每日比對訂單系統 vs 銀行入帳，確保金流正確：

```
訂單系統                    銀行對帳單
   │                          │
   ├── 訂單 A: $100 ──────── 入帳 $100 ✓
   ├── 訂單 B: $200 ──────── 入帳 $200 ✓
   └── 訂單 C: $150 ──────── 無入帳 ✗ → 人工處理
```

對帳失敗常見原因：
- 用戶付款後訂單未更新（Callback 遺失）
- 請款批次未送出（技術錯誤）
- 退款未同步

## 安全的金流實作原則

1. **不儲存原始卡號** — 使用代碼化（Tokenization）
2. **傳輸加密** — TLS 1.2+ / HTTPS
3. **交易冪等性** — 同一訂單不可重複扣款
4. **完整日誌** — 所有金流操作記錄不可篡改
5. **定期安檢** — 每年 PCI-DSS 或第三方支付安檢
6. **Saga 模式** — 金流失敗時補償交易（退款、取消訂單）
