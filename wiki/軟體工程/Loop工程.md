# Loop Engineering（反饋迴圈工程）

## 概述

Loop Engineering 是設計和管理 AI 輔助開發中多層反饋迴圈的實踐。從程式碼生成的即時檢查，到跨 Sprint 的迭代改進，每一層迴圈都決定了開發效率和品質。

```
開發反饋迴圈
┌────────────────────────────────────────────────────────────┐
│                                                            │
│  外層：人類 Prompt → AI 生成 → 人類驗證 → 迭代改進       │
│       ↓                                                    │
│  中層：程式碼 → 測試 → Lint → 自動修復 → 重新測試        │
│       ↓                                                    │
│  內層：AI 生成 → 編譯/語法檢查 → 修正 → 生成             │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

## 三層迴圈模型

### 外層迴圈（Human-AI Loop）

開發者與 AI 之間的高層次互動：

```
1. 人類描述任務（Prompt）
2. AI 產生程式碼 + 測試
3. 人類 Review 結果
4. 人類提供反饋
5. AI 修正
6. 重複直到驗收通過
```

**關鍵指標**：
- 每輪迭代時間（目標 < 5 分鐘）
- 通過率（一次 Prompt 就接受的比率）
- 迭代次數（平均幾輪完成任務）

### 中層迴圈（Test-Lint Loop）

自動化品質閘門：

```
AI 產生程式碼 → pytest → ruff lint → 報告 → AI 修正 → 重新測試
```

**關鍵原則**：
- 測試先行：先寫測試再寫實作
- lint 強制：格式問題不進 PR
- 閘門自動化：CI 伺服器自動執行

### 內層迴圈（Generation Loop）

AI 即時修正：

```
AI 寫程式碼 → 語法檢查 → 錯誤 → AI 自行修正 → 重新生成
```

這層迴圈對使用者完全透明，由 AI 模型內部完成。

## 反饋迴圈設計原則

### 1. 快速失敗

```
迴圈越短越好：
- 內層：毫秒級（語法檢查）
- 中層：秒級（測試 + lint）
- 外層：分鐘級（人類 Review）
```

### 2. 自動化閘門

每層迴圈的出口設置自動化檢查，失敗就不進入下一層：

```
生成 → [語法檢查] → [測試] → [人類 Review] → [合併]
           ↑            ↑            ↑
         內層閘門     中層閘門     外層閘門
```

### 3. 可見性

迴圈狀態必須對開發者可見：

```python
# 迴圈狀態追蹤
class LoopStatus:
    generation: int = 0        # 內層迭代次數
    test_failures: int = 0     # 中層失敗次數
    human_reviews: int = 0     # 外層 Review 次數
    elapsed_seconds: float = 0 # 總耗時
```

## 與其他工程的關係

```
Prompt 工程 → 啟動外層迴圈（人類描述任務）
Context 工程 → 提供迴圈所需的背景資訊
Harness 工程 → 設計迴圈的約束和閘門
Loop 工程   → 設計迴圈本身的結構和效率
Agentic 工程 → 讓 AI 自主驅動多層迴圈
```
