# 人機協作模式

AI 導向軟體開發中，人類與 AI 智慧體之間的分工與協作模式。

## 角色分工

```
人類（掌舵者）           AI（執行者）
─────────────────────    ─────────────────────
描述任務和意圖            產生程式碼
提供領域知識和背景        撰寫測試
驗證輸出品質              執行 lint 和格式化
做出設計決策              維護文件
管理專案方向              回應人類反饋
```

## 單人 + AI 模式

一位開發者搭配 AI 助理，完成從需求到部署的完整流程。

### 開發循環

```
1. 人類描述任務（Prompt 工程）
2. AI 產生程式碼 + 測試
3. 人類驗證結果（Review + 手動測試）
4. 反饋修正（迭代）
5. 提交到 Git（AI 發 PR，人類合併）
6. CI/CD 自動部署
```

### 關鍵成功因素

- **清晰的 AGENTS.md** — AI 的「操作手冊」，告訴 AI 專案結構和慣例
- **完整的測試覆蓋** — AI 修改後的回歸保障
- **版本控制** — 所有工件都在倉庫中，不在倉庫中的東西對 AI 不存在

### 適用場景

- 個人專案開發
- 新技術探索與原型驗證
- 套件或模組的獨立開發

## 大團隊協作模式

多人多 AI 的協作，需要更正式的合作流程。

### PR（Pull Request）流程

```
1. 開 feature branch
2. AI 開發 + 本地測試
3. 開發者 Push + 開 PR
4. CI 自動執行測試
5. 團隊 Code Review
6. Merge to main
7. 自動部署
```

### Code Review 要點

```
- 功能正確性 — 是否滿足需求
- 測試覆蓋 — 有測試嗎？測試合理嗎？
- 程式碼品質 — 可讀性、命名、架構
- 安全性 — 有洩漏敏感資訊嗎？
- Lint/Format — 是否符合規範
```

### AI + 團隊協作工作流程 (Harness 模式)

```
1. 人類開 issue / 寫需求
2. AI 在 feature branch 開發 + 測試
3. AI 提交 PR（含測試結果）
4. 人類 Code Review + 合併到 main
5. CI/CD 自動部署
```

核心原則（來自 Harness 工程）：
- 不在倉庫裡的東西對 AI 不存在
- AGENTS.md 是目錄，只指路（~100 行）
- 專職 linter + CI 驗證
- doc-gardening 智慧體定期掃描過時文檔

## 常見陷阱

```
問題                    解決方案
────────────────────     ────────────────────
不完整執行               明確要求完成所有任務
工具誤用                 分階段授予工具權限
上下文遺忘               使用 todo.md 記錄狀態
幻覺（Hallucination）    強制引用來源
過度依賴 AI              保留人類最終決策權
```
